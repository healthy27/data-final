# 데이터 품질 감사로 다시 설계한 기업 고용·수익성 분석

## 프로젝트 소개

기업의 재무정보와 직원수로 수익성을 분석한 수업 프로젝트를 재구성했다.
제공받은 5개 Excel·CSV 파일을 대조해 전처리 오류를 정량화하고, 대체 전 자료에서 분석용 값을 다시 추출했다.
2021년 재무·고용 정보로 2022년 적자를 구분하는 실험을 수행했다.
핵심 결과는 높은 예측 점수의 재현이 아니라, 데이터 처리의 영향을 확인하고 모델의 실익을 검증한 것이다.

**현재 범위:** 138개 기업의 제공 자료를 감사하고 125개 기업, 적자 25개의 탐색 실험을 완료했다.
통화·연결 범위·실제 수집 연도·공시 시점은 제공 파일에 없어 원문 대조를 완료하지 못했다.
따라서 아래 실험은 제공 자료의 명목상 2021→2022년 전환에 대한 기업 간 검증이다.

## 자료와 재현 경로

| 제공 파일 | 내용 | 행 수 | 기업 수 |
| --- | --- | ---: | ---: |
| kospi100.xlsx | 대체 전 재무 계정 | 1,969 | 74 |
| kosdaq100.xlsx | 대체 전 재무 계정 | 2,825 | 65 |
| KOSPI_KOSDAQ_merge (2).xlsx | 두 재무 파일의 병합 | 4,794 | 138 |

| KOSPI_KOSDAQ_merge (1).xlsx | 순이익·직원수 요약 | 132 | 131 |

74+65와 138의 차이는 두 재무 파일에 같은 기업이 포함되어 있기 때문이다.
파일명에 포함된 시장명은 실제 거래소 분류가 검증됐다는 뜻으로 사용하지 않았다.
원본 Excel 2개를 단순 연결한 결과와 병합 파일의 값·행 순서가 일치함을 확인했다.
원본은 수정하지 않고 SHA-256, 시트명, 원본 행 번호를 기록했다.

재현 코드는 `legacy.py`와 `legacy_analysis.py`에 있으며,
정규화한 입력은 `data/reference/legacy_panel.csv`, 검증 결과는 `reports/legacy/`에 있다.
전체 원본은 저장소에 복사하지 않았다. 원본 대조는 `data-final audit-legacy --source-dir ...`로 재실행한다.

## 1. 결측값이 없다는 것이 좋은 데이터라는 뜻은 아니었다

**문제와 근거.** 병합 전 재무 파일에는 2021년 598개, 2022년 536개의 결측 셀이 있었다.
최종 CSV에서는 이 1,134개 셀이 각각 33,087,031,231과 33,898,331,929로 채워져 있었다.
이 값은 해당 연도 전체 재무 열의 중앙값과 일치했다. 원래 관측된 금액의 변경은 0건이었다.

**왜 중요한가.** 같은 열에는 매출·현금흐름·주당이익 등 의미와 규모가 다른 계정이 섞여 있다.
전체 중앙값은 특정 계정의 합리적인 대체값이라고 볼 수 없다.
특히 정답인 순이익을 양수 중앙값으로 채우면 실제 손익을 모르는 기업에 흑자라는 정답이 생긴다.

**고려한 방법.** 최종 CSV를 그대로 사용하거나, 모든 중앙값과 같은 숫자를 지우거나,
대체 전 원본과 키를 맞춰 결측 상태를 복원할 수 있었다.
숫자가 중앙값과 같다는 이유만으로 지우면 실제 관측값까지 없앨 수 있다.

**이번 선택과 장단점.** 대체 전 재무 파일에서 다시 추출했다.
동일 기업·원본 계정의 반복 순번까지 맞춰 비교해 다대다 조인으로 감사 건수가 부풀려지는 것을 방지했다.
장점은 관측값과 대체값을 출처로 구분한다는 점이고, 단점은 대체 전 파일이 있어야 한다는 점이다.
직원수 원본 응답처럼 제공되지 않은 단계까지는 복원할 수 없다.

**구현과 결과.** 입력 변수의 남은 결측은 학습 fold 안에서 중앙값으로 대체했다.
2022년 정답 결측 기업 6개는 제외했다. 결측 정답을 채우는 경로는 제거했다.

## 2. 계정 이름을 비슷하게 만드는 과정에서 의미가 바뀌었다

**문제와 근거.** `자본과부채총계 → 부채총계`가 86행,
`부채와자본총계 → 자본총계`가 10행 있었다.
표준화 후 기업·계정 키가 중복된 그룹은 429개, 추가 행은 540개였다.
이는 모두 오류라는 뜻은 아니지만, 무조건 합산해도 되는 구조는 아니다.
총이익과 계속·중단영업, 세전이익, 주당이익도 서로 다른 개념이다.

**왜 중요한가.** 자산=부채+자본이라는 관계에서 총계를 부채나 자본으로 재명명하면 비율이 달라진다.
부분항목과 합계가 같은 이름이 된 뒤 `sum`을 적용하면 중복 계산이 생긴다.
기계학습 모델은 이런 값도 숫자로 받아들이므로 학습이 성공했다고 오류가 사라지지 않는다.

**고려한 방법.** 부분 문자열 매칭은 적용 범위가 넓지만 잘못된 매칭 위험이 높다.
표준 계정 ID 매핑이 가장 명확하지만 이 제공 자료에는 ID가 없다.
당장 가능한 보수적인 방법은 제한된 정확한 계정명 허용 목록이다.

**이번 선택과 장단점.** 공백과 번호만 정리하고 의미가 같은 이름만 허용했다.
동일 후보 값은 한 번만 쓰고, 후보 간 값이 다르면 결측·충돌로 기록했다.
장점은 잘못된 자동 합산을 피하는 것이고, 단점은 사용할 수 있는 계정과 표본이 줄어든다는 것이다.
수집 코드에는 별도로 표준 account_id 우선 매핑을 구현했다.

**구현과 결과.** 코오롱티슈진은 제공 원본의 2022년 순이익이 -8,619,693인데,
기존 표준화·대체·합산 결과는 +33,881,092,543이었다. 통화는 미확인이라 원 단위라고 부르지 않는다.
재추출로 이 기업의 손익 부호를 보존했다. 이를 근거로 정답 생성 전 계정 의미 검증이 필요함을 입증했다.
또 현대자동차의 실제 제공 순이익은 존재했지만 기존 표준화 타깃 열에 잡히지 않아 중앙값으로 대체되던 경로도 발견했다.

## 3. 중복 기업과 충돌 값을 먼저 해결했다

**문제와 근거.** 코리아써키트의 재무 행 33개가 두 자료에 동일하게 반복됐다.
순이익·직원수 요약에는 같은 기업이 두 행으로 있고, 2021년 직원수가 1,337과 1,208로 충돌했다.
서로 다른 기업 18개에서는 2021·2022년 직원수 쌍이 두 그룹으로 반복됐다.
반복 자체만으로 잘못된 값이라고 확정할 수는 없다.

**왜 중요한가.** 중복 기업이 학습·평가에 나뉘어 들어가면 같은 기업을 이미 본 모델을 평가하게 될 수 있다.
재무를 합산하면 기업의 크기가 부풀고, 직원수를 첫 행으로 고르면 결과가 행 순서에 의존한다.

**이번 선택.** 회사별 각 연도의 유일한 관측값을 추출했다.
직원수 충돌 1개 기업·연도는 결측으로 남겼다. 회사별 한 행을 만든 뒤 외부 fold에서 회사 이름의 교집합이 없음을 검사했다.
이름 기반 식별은 이 파일 안에서는 유용하지만, 같은 기업의 다른 이름이나 합병 이력을 검증하지 못한다.
후속 수집은 DART 고유번호를 키로 사용한다.

**민감도 분석.** 본 분석에 포함된 반복 직원수 쌍 기업 15개를 제외한 110개 기업에서도 로지스틱 비교를 반복했다.
이는 문제 가능성이 있는 자료가 결론에 미치는 영향을 보는 진단이며, 제외 기업이 오류라고 판정하는 절차는 아니다.
반복 쌍 표시는 2022년 값도 보고 만든 사후 진단이다. 예측 변수로 사용하지 않았다.

## 4. 예측 질문과 데이터의 시간을 맞췄다

**기존 문제.** 기존 모델은 2022년 세전순이익·영업이익 등 380개 항목으로 같은 해 흑자 여부를 분류했다.
같은 해의 상태 설명에는 쓸 수 있지만 미래 손익 예측으로 해석하기에는 정답과 너무 가까운 정보가 포함된다.

**이번 선택.** 명목상 2021년의 재무 비율 4개와 직원수 1개로 2022년 적자를 분류했다.
재무 변수는 순이익/자산, 순이익/매출, 영업이익/매출, 부채/자산이다.
고용 변수는 log(1+2021년 직원수)이다. 2021→2022년 직원수 증가율은 예측 입력에서 제외했다.
2019·2020년이 없으므로 이전 기간의 직원수 증가율도 임의로 만들지 않았다.

**왜 비율을 썼나.** 제공 자료에 통화 정보가 없어 기업 간 금액 크기를 직접 비교하기 어려웠다.
같은 기업 안에서 분자·분모의 통화와 범위가 같다면 비율은 단위 차이를 줄일 수 있다.
다만 이 가정도 원문 확인이 필요하며, 비율만으로 연결/별도나 실제 연도 혼용 문제가 해결되지는 않는다.
매출·자산이 0이거나 없으면 비율을 결측으로 남겼다.

**장단점.** 적은 표본에서 의미가 명확한 소수 변수를 쓰고 기업 크기 영향을 줄일 수 있다.
반면 계정 누락으로 결측이 생기고, 작은 분모에서 극단값이 생길 수 있다.
규모 정보와 업종 차이를 모두 설명하지도 못한다.
통화·공개일·실제 사업연도가 검증되기 전에는 미래 정보 차단을 완전히 입증했다고 말하지 않는다.

**최종 표본.** 138개 중 2022년 타깃 결측 6개와 2021년 재무 비율이 2개 미만인 7개를 제외해 125개를 분석했다.
손실 기업은 25개, 비율은 20%다. 제외 목록과 이유는 `eligibility.csv`에 기록했다.

## 5. 전처리와 모델 선택을 평가 데이터에서 분리했다

**문제.** 전체 자료에서 중앙값을 구한 뒤 분할하면 평가 기업의 분포가 학습 전처리에 참여한다.
여러 모델 중 가장 높은 외부 평가 점수를 고르고 그것을 그대로 성능으로 제시하면 선택 편향도 생긴다.

**검토한 대안.** 단일 70:30 분할은 간단하지만 적자 25개에서는 분할 하나에 결과가 흔들릴 수 있다.
다년도 시간 검증이 예측 질문에 더 적합하지만 제공 자료에는 한 번의 연도 전환만 있다.
따라서 이번 자료에서 실행 가능한 기업 간 반복 교차검증을 사용했다.

**구현.** 5-fold 층화 분할을 seed 42–46의 5회 반복으로 고정했다.
외부 학습 기업 안에서 3-fold 검증으로 4개 모델·피처 조합을 AP 기준으로 선택했다.
선택한 조합을 외부 평가 기업에 적용해 OOF 예측을 만들었다.
결측 대체·결측 표시자·스케일링은 매 Pipeline의 학습 데이터에서만 학습한다.

**장단점.** 작은 표본을 효율적으로 쓰고 모델 선택과 평가를 분리할 수 있다.
계산량이 늘고 fold별 적자 기업이 5개뿐이라 성능이 불안정하다.
반복 결과는 독립 표본이 아니므로 최소·최대 범위를 95% 신뢰구간처럼 부르지 않았다.
이 방식은 여러 미래 연도나 전혀 새로운 기업 모집단의 성능을 보장하지 않는다.
관련 기업집단에 따른 의존성도 현재 정보로 완전히 통제하지 못한다.

## 6. 복잡한 모델을 쓰기 전에 단순 기준과 비교했다

로지스틱 회귀는 작은 표본에서 안정성과 설명 가능성을 얻기 위한 선택이다.
선형적인 결정 구조가 제한이고 극단 비율에 민감할 수 있어 비선형 관계를 학습하는 작은 부스팅도 비교했다.
부스팅은 비선형 상호작용을 다룰 수 있지만 작은 표본에서 과적합과 불안정성이 커진다.
별도의 대규모 파라미터 탐색은 하지 않았다.

학습 적자 비율만 출력하는 기준과 전년 적자 상태를 유지하는 기준을 반드시 넣었다.
실제로 유용한 기준이 이미 충분한 성능을 내면 복잡한 모델을 운영할 이유가 약해지기 때문이다.
적자가 20%라 모두 흑자라고 예측해도 정확도는 80%다.

### 실제 결과

아래는 5회 반복별 전체 OOF 점수의 평균이며, 양성 클래스는 적자다. 임계값은 0.5로 고정했다.

| 방법 | ROC-AUC | AP | 정확도 | 적자 재현율 |
| --- | ---: | ---: | ---: | ---: |
| 학습 적자 비율 기준 | 0.5000 | 0.2000 | 80.00% | 0.0% |
| 전년 적자 상태 유지 | 0.7750 | 0.4816 | 85.60% | 64.0% |
| 재무 로지스틱 | 0.7510 | 0.5796 | 84.64% | 32.0% |
| 재무+직원수 로지스틱 | 0.7615 | 0.5807 | 84.96% | 34.4% |
| 재무 부스팅 | 0.8004 | 0.5301 | 85.44% | 52.0% |
| 재무+직원수 부스팅 | 0.7875 | 0.5736 | 84.96% | 47.2% |
| 내부 검증에서 선택한 절차 | 0.7712 | 0.5708 | 83.52% | 38.4% |

**해석.** 내부 검증 선택 절차는 AP에서 전년 상태 기준보다 높았지만, 정확도와 적자 재현율은 낮았다.
ROC-AUC 역시 전년 상태 기준을 넘지 못했다.
복잡한 모델이 모든 지표에서 좋아졌다고 주장할 수 없다.
손실 기업을 놓치는 비용과 잘못 경고하는 비용이 정해지지 않았으므로 결과를 본 뒤 임계값을 임의 조정하지 않았다.
비용 기반 임계값을 검토할 때는 내부 검증에서 선택하고 외부 fold에서 다시 평가해야 한다.

기존 95.24%와 이번 점수는 타깃 시점·표본·변수·평가 방식이 달라 직접적인 성능 증감 비교가 아니다.

## 7. 직원수가 도움이 된다는 주장도 비교 실험으로 확인했다

**질문.** 재무정보에 직원수를 더하면 추가적인 정보가 생기는가?
같은 모델, 같은 표본, 같은 분할에서 피처만 바꾸는 ablation을 설계했다.
모델 종류와 피처 구성을 동시에 바꾼 점수 차이를 직원수의 가치라고 부르지 않는다.

로지스틱 AP는 0.5796에서 0.5807로 평균 +0.0011 변했다.
seed별 차이는 -0.0104에서 +0.0200 사이였다. 두 번은 개선, 세 번은 악화됐다.
반복 직원수 쌍을 제외한 110개 기업에서는 AP가 0.5884에서 0.5797로 오히려 낮아졌다.
부스팅에서는 AP가 개선됐지만 AUC와 적자 재현율은 낮아졌다.

**결론.** 이번 자료에서는 직원수 추가가 안정적으로 개선을 만든다는 근거가 충분하지 않았다.
직원수의 영향이 없다고 입증한 것도 아니다. 표본 크기, 이미 대체됐을 가능성이 있는 직원수,
수집 범위의 불확실성이 결론을 제한한다.
새로운 피처를 추가했다는 사실보다 추가 가치가 있는지 확인하고 과장하지 않은 판단이 성과다.

## 8. 상관관계와 예측 성능을 구분했다

직원수 변화율과 순이익 변화/전기 자산의 관련성을 완전 관측 102개 기업에서 계산했다.
Pearson r=0.1232, p=0.2175, Spearman r=0.1524, p=0.1261이었다.
반복 직원수 쌍을 제외한 88개 기업에서도 Pearson r=0.1355, Spearman r=0.1727이었다.

Pearson은 선형 관련성을 보여주지만 이상치에 민감하다.
Spearman은 순위를 사용해 큰 금액 차이에 덜 민감하지만 선형 관계의 크기를 나타내지는 않는다.
두 방법의 방향과 크기를 함께 확인했다. p값은 탐색용이며 여러 분석 후 확증적 발견으로 해석하지 않았다.
유의수준 0.05에서 충분한 근거를 얻지 못했다고 표현하고, 관계가 없다고 확정하지 않았다.
업종·경기·기업 규모 등 다른 원인이 있으므로 인과 효과로 해석하지 않는다.

## 9. 재현성과 소프트웨어 품질도 결과로 남겼다

Colab의 수동 업로드·Power Query 변환을 Python 명령으로 재실행할 수 있게 했다.
파일 SHA-256, 원본 행, 계정 허용 목록, 제외 사유, 외부 fold 배치, 내부 선택 점수, OOF 예측을 저장한다.
`uv.lock`으로 의존성을 고정하고 GitHub Actions에서 테스트·예제 실행을 검사한다.
정답 결측 제외, 다른 개념의 계정 분리, 중복 조인, 미래 입력 차단, 기업별 fold 분리를 회귀 테스트에 포함했다.

장점은 변경 후 오류가 다시 생기는지 자동으로 확인할 수 있다는 것이다.
단점은 코드 구조와 테스트 유지 비용이 생긴다는 점이다.
이 프로젝트에는 실시간 서버나 복잡한 MLOps 플랫폼보다 이 정도의 실행 기록과 자동 검사가 규모에 맞는다.

## 남은 한계와 후속 순서

현재 자료는 제공 파일끼리의 일관성은 검사했지만 실제 공시 원문과의 일치까지 입증하지 않았다.
동일 기업·연도 안에서 통화·연결 범위가 같다는 가정, 원래 수집 코드의 전년도 fallback 가능성이 남는다.
새 DART 수집기는 연간 OFS를 고정하고 account_id·접수번호·시각을 보존하도록 구현했지만,
신규 인증키를 사용한 실제 수집을 완료했다고 주장하지 않는다.

후속 순서는 다음과 같다.

1. 검증된 기업 고유번호·보고서 기간·통화·접수번호로 원천을 다시 확보한다.
2. 공시 시점별 버전과 당시 상장 모집단을 확보해 시간·생존편향을 점검한다.
3. 여러 연도와 업종으로 확대해 미래 연도 및 기업집단 분리 검증을 수행한다.
4. 손실 탐지의 업무 비용을 정하고 임계값과 확률 교정을 내부 검증에서 선택한다.
5. 데이터 정의와 사용 목적이 확정되면 대시보드나 배포를 추가한다.

LLM·SHAP·대시보드는 현재 확인된 원천 정합성이나 표본 부족을 직접 해결하지 않는다.
도구의 유행보다 이번 자료의 병목에 맞춘 선택을 했다.

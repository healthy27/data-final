# 포트폴리오·면접에서 설명하기

## 현재 구현에 대해 말할 수 있는 것

> 기업 재무·고용 분석 프로젝트에서 연도 대체, 타깃 결측 대체, 분할 전 전처리 문제를 발견하고,
> 명시적인 데이터 계약과 연도별 검증을 갖춘 Python 파이프라인으로 재구성했다.
> 재무 변수만 사용한 모델과 고용 변수를 추가한 모델을 비교하고,
> 합성 데이터 통합 테스트와 CI를 통해 실행 경로를 검증했다.

이 설명도 직접 코드를 읽고 설계 의도를 설명할 수 있을 때 사용하세요.
AI 도구의 도움을 받은 구현이며, 본인이 수행한 수집·분석·설계 검증 범위와 도움받은 범위를 구분하는 것이 좋습니다.

## 아직 주장할 수 없는 것

- “기업 적자를 95% 이상 정확도로 예측했다.”
- “직원수 변화가 기업 이익에 영향을 준다는 사실을 입증했다.”
- “실제 투자에서 미래 정보를 전혀 쓰지 않는 모델을 만들었다.”
- “전체 코스피·코스닥 기업을 대표한다.”

## 5분 발표 흐름

1. **문제:** 높은 분류 점수가 실제로 무엇을 뜻하는지 의심했다.
2. **진단:** 연도 대체와 타깃 대체, 같은 해 손익 입력, 전처리 누수를 코드에서 찾아냈다.
3. **설계:** 기업코드·보고서 범위를 고정하고 다음 해 타깃과 과거 연도 검증을 도입했다.
4. **비교:** 단순 기준 모델과 작은 모델, 고용 변수 유무를 같은 조건에서 비교했다.
5. **검증 범위:** 현재는 합성 데이터 실행 검증이며 실데이터의 성과는 아직 확정하지 않았다.
6. **한계:** 정정공시·공개 시점·표본 편향·인과 해석을 별도로 설명한다.

## 실데이터 프로젝트 완료 기준

- [ ] 선정 시점·업종·제외 기준을 기록한 기업 모집단 확보
- [ ] 새 DART 키로 수집 성공 및 응답 캐시 보존
- [ ] 표본 기업의 재무·직원수를 원문 보고서와 대조
- [ ] 누락률·계정 매핑·직원수 범위 감사
- [ ] 충분한 적자 표본과 검증 연도 확보
- [ ] 고용 변수 추가 전후의 검증 결과 해석
- [ ] 최종 평가 연도를 반복 튜닝에 사용하지 않았는지 점검
- [ ] 실패 사례와 산업별 성능 차이를 정리
- [ ] 실데이터 리포트를 근거로 결과·한계를 README에 반영

## 후속 확장 우선순위

첫째는 point-in-time 공시 데이터와 당시 모집단입니다. 모델 종류를 늘리기보다 정보 시점의 정합성을 먼저 확보해야 합니다.
그 다음은 업종별 오류 분석과 고용 변수 추가 가치의 안정성입니다.
데이터가 충분해지면 기업 단위 외부 검증, 비용 기반 임계값, 교정된 확률을 검토할 수 있습니다.
대시보드·SHAP·MLflow 같은 도구는 이때 전달·실험 관리 요구가 생기면 추가합니다.

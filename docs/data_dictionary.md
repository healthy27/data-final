# 데이터 계약과 수집 감사

이 문서의 OFS·통화 계약은 새 DART 수집 경로에 적용합니다.
제공 자료는 이 기준을 충족한다고 가정하지 않고 별도 `legacy_unverified` 데이터로 유지합니다.
`data/reference/legacy_panel.csv`의 통화·연결 범위·기간은 unknown이며,
회사 이름·연도·관측 재무 값·직원수·충돌 상태·반복 쌍 플래그를 보존합니다.
세부 설계는 [제공 자료 방법론](legacy_methodology.md)을 참고하세요.

CSV를 읽을 때 `corp_code`, `reprt_code`는 문자열로 읽습니다. 빈 숫자 값은 결측입니다.

| 필드 | 의미 | 검증 |
| --- | --- | --- |
| corp_code | DART 고유번호 | 8자리, year와 결합해 유일 |
| company | 기업 표시명 | 필수, 결합 키로 사용 안 함 |
| year | 실제 사업연도 | 정수, 2015–2100 |
| fs_div | 재무제표 범위 | OFS만 허용 |
| reprt_code | 보고서 코드 | 11011만 허용 |
| data_kind | 자료 구분 | dart / synthetic 중 하나, 혼합 금지 |
| revenue | 매출액, 원 | 음수 불허, 없으면 결측 |
| operating_income | 영업이익, 원 | 손실은 음수 |
| net_income | 당기순이익, 원 | 손실은 음수, 타깃 대체 금지 |
| assets | 자산총계, 원 | 음수 불허 |
| liabilities | 부채총계, 원 | 음수 불허 |
| employees | 직원수, 명 | 음이 아닌 정수, 결측 가능 |

수집은 전체 재무제표 API에서 표준 account_id를 우선하고, 없는 경우 허용한 정확한 계정명만 사용합니다.
`수익`처럼 넓은 부분일치로 계정을 고르지 않습니다. 동일 계정 후보가 서로 다른 값을 가지면 합산하지 않고 모호한 값으로 남깁니다.
동일 값의 IS/CIS 반복은 하나의 값으로 취급합니다. 외화 표시 행은 사용하지 않습니다.

## 직원수 집계

사업부문 × 남/여 상세 행의 `sm`만 합산합니다. 합계·총계 행을 다시 더하지 않습니다.
같은 그룹이 반복되거나 일부 상세 값이 누락되면 결측으로 보존합니다.
인식하지 못하는 형태를 임의로 추정하지 않습니다. 상세행의 집계가 성공해도 `detail_sum_review_required`로 표시합니다.
보고서의 직원 정의, 사업부문 중첩, 파견·해외법인 포함 여부 등은 원문 확인이 필요합니다.

## 결과와 감사 산출물

- `panel.csv`: 회사-연도별 정규화 입력
- `panel.audit.json`: 계정별 상태·매칭 방법·접수번호, 직원수 집계 상태
- `data/raw/dart/*.json`: 인증키를 제외한 원본 응답
- `*.meta.json`: 요청 조건, UTC 수집 시각, 원본 SHA-256
- `metrics.json`: 입력·소스 해시, 라이브러리 버전, 선택 규칙, 평가·불확실성
- `validation_folds.csv`: 모델·피처·연도별 검증 내역
- `examples.csv`: 실제 특징·타깃 연결을 점검하는 감사 테이블
- `predictions.csv`: 최종 연도 기업별 예측값

현재 고유번호 명부는 종목코드의 정확한 일치에 사용됩니다. 과거의 기업명·상장 상태·합병 이력을 자동 복원하지 않습니다.
원래 엑셀의 연결/별도·기간·기업코드 정보가 없으면 이 계약으로 임의 변환하지 말고 원천을 다시 확인해야 합니다.
